当前采用完整球拍、真实球网和固定规则的原生 PhysX 评估链。最近一次已完成的独立冷评估是固定顺序的 128 例，选中共享目标偏置候选（世界坐标偏置 `[0, -0.10, +0.04] m`）：

| 完整成功 | **0/128** | 正式最差 200 例面板 ≥50% |
| 合格空中拍线触球 | **29/128 = 22.66%** | ≥70% |
| 空中触球后的合格恢复 | **9/29 = 31.03%** | ≥85% |
| 合格攻击出球 | **0** | 必须满足速度、方向、过网、落点、恢复和零故障 |
| 数值故障 | **0** | 0 |

这 128 例中记录到 59 次实际球拍接触，27 次越网并首次落在合法对场，22 次首次落入原目标区；但没有任何回合同时满足完整的攻击出球和恢复条件，因此当前仍未达标。恢复先验、空中反向运动、站姿恢复和动量挥拍候选均已做过独立冷评估，尚未产生完整成功。

GPU0 已完成下一阶段高速度挥拍搜索，并对搜索最佳候选做了独立冷 128 例复评：在不改变场地、目标区、球拍模型、硬件限制或验收门槛的前提下，把控制器的期望拍面出球方向设为 `[8, 0, -1] m/s`，并测试手臂增益与受限腿部联动。四个搜索候选和独立冷评估仍全部为 0 次完整成功、0 次攻击出球；最佳候选的冷评估结果与共享目标基线一致（29 次空中触球、9 次恢复）。

## 当前方案

1. 保留冻结的原始 actor、观测归一化、地面初始化和 128 例顺序，使用教师式接触时序、挥拍和恢复先验做候选搜索。
2. 所有候选在原生 PhysX 中运行；记录实际拍线接触、触球时刻的球拍点速度、球的实际出球速度、越网、首次落地、目标落点、恢复以及每类故障。
3. 采用完整球拍的有限质量和惯量模型。控制器中的目标速度只用于产生动作，不能直接替代球的实测出球速度。
4. 高速度搜索固定期望出球 `[8,0,-1] m/s`，候选只改变手臂增益或腿部速度增量上限；候选 0、1、2、3 的搜索结果分别为 29/9、23/10、21/9、18/11（空中触球/条件恢复），攻击出球和完整成功均为 0。对搜索最佳候选做独立冷评估后，结果为 **29/128 空中触球、9/29 恢复、0 攻击、0 完整、NF0**。这说明目标速度指令没有转化为足够的真实球速。
5. 通过后续正式的两个固定 200 例面板，以较差面板计算完整成功率、空中触球率和条件恢复率；当前 128 例结果只是开发阶段证据，不能代替正式验收。

## 完整场景描述

### 场地、坐标和球网

- 羽毛球双打外框：全长 **13.4 m**，双打宽 **6.1 m**，单打有效宽 **5.18 m**，地面 `z=0`。
- 每个环境使用本地坐标，`x` 从机器人半场指向对方半场；球网平面 `x=1.5 m`。机器人半场为 `x∈[-5.2,1.5]`，对方半场为 `x∈[1.5,8.2]`。
- 球网中心高度 **1.524 m**，两侧高度 **1.55 m**，宽 **6.1 m**，等效悬挂带深 **0.76 m**；使用 64 条 GPU primitive strips 表示下垂网带，碰撞和评分使用同一网面定义。
- 网柱位于 `y=±3.075 m`，半径 **0.025 m**。环境间距为 `0 m`，用于避免大世界坐标的 float32 累积误差，不改变场地几何。

### 机器人和完整球拍

- 机器人为 Go2 浮动基座，安装标准 AgileX PiPER 六轴机械臂；控制输入包含 12 个腿关节和 6 个机械臂关节，共 18 个执行关节。
- `full_racket_v4_r3` 是固定到 PiPER link6 的完整球拍：夹具、握把、杆、拍框和拍线面均建模，球拍总长度 **0.675 m**，拍框外长 **0.25 m**、外宽 **0.20 m**。
- 球拍是带有限质量和惯量的刚性工具，不是无质量点工具。配置记录 5U 球拍质量假设：球拍 **0.078 kg**、拍线 **0.005 kg**、加装握把 **0.005 kg**、等效夹具 **0.065 kg**、杆 **0.018 kg**，并使用组合惯量。
- 拍线碰撞面由 32 边形拍面和 64 条内切薄条构成；拍框、杆、握把和夹具分别记录接触类别。夹具不计作拍面，机体、夹具和拍框均继续受己方半场工程约束。

### 球、初始化和时序

- 使用 **5.2 g** 刚性球代理模型，含当前仿真中的二次阻力；结果不宣称真实羽毛球空气动力学或赛事认证。
- 每回合从地面初始化开始，准备时间 **2 s**；初始根部位置 `[0, 0, 0.323] m`，不使用外力修正或事后发球状态。
- 发球位置 `[1.1, 0, 1.8] m`，法向 `[1,0,0]`，`t=2.75 s`，初速度 `[0,0,0]`；主动发球前球观测遮蔽。
- 物理步长 **62.5 µs**，策略步长 **10 ms**，单回合 **8 s**；初始姿态和 A/B 扰动来自冻结评估配置。

### 目标区和完整成功定义

- 对方目标区固定为 `x∈[2,4] m`、`|y|≤1 m`。它属于验收协议，本轮没有放宽。
- 合格空中触球必须是飞行中的实际拍线受力接触，首次接触为己方合法球拍接触。
- 完整成功还必须同时满足：实际出球 `vx>0`、`vz≤−1 m/s`、速度 **≥8 m/s**；球实际越网；首次落地在对方合法场地和上述目标区；机器人完成连续恢复；没有机器人触网、身体/夹具越界、球拍侵入、错误返回、网阻挡或数值故障。
- 恢复是条件指标，只在合格空中触球的回合中计算，并遵循原协议的起跳和连续 **0.8 s** 稳定条件。

## 主要失败原因

1. **击球能量不足。** 已完成的候选有实际拍线接触和部分合法落点，但实际球出球速度没有同时达到 8 m/s、向前且向下的攻击门槛，因此攻击计数为 0。
2. **接触时序和横向命中率不足。** 128 例只有 29 例形成合格空中拍线触球，距离 70% 目标仍有明显差距；预测到球并不等于拍面中心在正确时刻、正确姿态接触。
3. **击球后的支撑与收束不稳定。** 最近独立冷评估只有 9/29 条件恢复合格；腿部制动、躯干姿态和机械臂收拍仍会出现非足部触地或回合提前中断。
4. **规则链还有离散故障。** 当前选中候选计有机器人触网 3 次、工程身体越界 3 次、错误返回 6 次、网阻挡 7 次；数值故障为 0 只说明仿真数值稳定，不代表回合规则完整。
5. **这是教师控制适配和先验搜索，不是已完成训练收益。** 原始 actor 和归一化保持不变；正式 2×200 固定面板尚未通过，所以不能把开发阶段的部分落点或视频片段称为完整扣杀成功。

### 结构化动作生成试验

依据“先反解击球事件，再联合优化全身轨迹”的调研方向，新增了只使用公开时钟、以实际拍头位置增量表达的三段事件控制器：击球前准备、击球窗口和收拍恢复。零增量候选精确复现了共享基线；三个非零候选在原生冷 128 上分别得到：

| 候选 | 空中触球 | 合格恢复 | 攻击 | 完整 | 数值故障 |
|---|---:|---:|---:|---:|---:|
| 零增量 | 29 | 9 | 0 | 0 | 0 |
| 小幅手臂三段增量 | 20 | 1 | 0 | 0 | 0 |
| 大幅手臂三段增量 | 15 | 1 | 0 | 0 | 0 |
| 手臂＋腿三段增量 | 15 | 3 | 0 | 0 | 0 |

随后对教师的期望拍头速度向量做了事件目标搜索，基线 `[0.8,0,-1.2]` 以及 `[2,0,-1.5]`、`[3,0,-1.5]`、`[4,0,-1.5]` 四个目标均没有产生攻击出球；后 3 个候选的空中触球/恢复分别为 **23/5、23/7、22/6**。这说明目标速度指令本身不能代替可执行的全身动力学轨迹，直接叠加位置增量也会破坏接触时序。

### 路线决定

当前保留的最佳可复现源仍是共享目标偏置 `[0,-0.10,+0.04] m`，不再继续堆叠固定偏置、速度目标或小残差。证据支持把下一阶段改成真正的事件生成器：对同一来球先求接触时刻、拍面和所需拍头速度，再把准备、起跳、腾空击球、着地和恢复作为一条全身轨迹联合优化；候选轨迹必须经过原执行器和原生 PhysX 实际执行后，才进入 BC/DAgger 或 RL 数据集。当前新增试验仅证明了“简单的叠加式事件模板”不足，不能据此宣称硬件不可行。

新增程序保存在工作区 `scripts/search_shared_structured_event_v1.py` 与 `scripts/search_shared_velocity_targets_v1.py`，中间权重、轨迹和视频仍不上传 GitHub；本报告只记录可复核的汇总结果。

### 完整事件参数 CEM（2026-10-28）

为验证“全身事件参数联合搜索”是否能直接替代事件生成器，修正并运行了 `scripts/search_shared_full_event_cem_v1.py`。参数布局按实际控制器分成 38 维：24 个主教师参数、击球平面与时序、6 个手臂速度种子、5 个恢复参数和 1 个拍面法向偏置；每个维度使用其消费模块已经声明的边界。实验在 GPU0 的原生 PhysX 中执行 1 代、4 个候选、每个候选固定 128 条训练回合，共 **409,600 个控制环境步**。

| 候选 | 空中拍线触球 | 合格恢复 | 攻击 | 完整 | 数值故障 | 平均训练部分分数 |
|---|---:|---:|---:|---:|---:|---:|
| 0（零扰动基线） | 29 | 9 | 0 | 0 | 0 | 9.8690 |
| 1 | 0 | 0 | 0 | 0 | 0 | -1.9892 |
| 2 | 0 | 0 | 0 | 0 | 0 | -1.0816 |
| 3 | 0 | 0 | 0 | 0 | 0 | -0.9908 |

候选排序为 `[0, 3, 2, 1]`，所以没有产生可替换的教师。零扰动候选精确复现 29/9 基线，证明参数写入、episode 关联和评分链保持一致；其余候选虽然没有数值故障，却破坏了原有击球时序，说明在当前分段控制器上对全 38 维做独立随机扰动不是有效的完整事件生成方法。结果收据和逐候选汇总保存在本地 `reports/G07_full_racket_v5/full_event_cem4_n128_02/execution_receipt.json` 与 `metrics.json`，未上传大体积轨迹、几何快照或权重。

因此下一步不继续扩大这种全维盲采样，而是把搜索降到经过反解约束的事件变量（接触时刻、可行拍面、实际拍头速度和可恢复落地状态），并将这些变量联合传入全身轨迹优化；候选仍须经过原执行器和原生 PhysX 的完整回合验收后才能用于 BC/DAgger 或 RL。
