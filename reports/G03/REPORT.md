# G03 native interface and PPO re-audit

The public smoke command ran 32 native environments for 2000 policy steps, plus virtual and real-ball interface probes. All stages use the same 794-float observation, with audited joint order, body-frame reference-point velocities, tool state, contact, ball and history-valid masks, event commands, measured phase, elapsed clock and prior action. Partial resets isolate physical state/history. Timeout final observations are captured before reset; a known-value regression distinguishes V(final)=7 from V(previous)=2 and V(reset)=-50 and excludes simultaneous true terminals.

Stock locked RSL-RL PPO performed 10 fresh updates with finite losses, gradients and parameters. The adapter changes timeout reward augmentation and checkpointing, not the PPO optimizer/update equations. Independent processes restored model, normalizers, optimizer, scheduler rate, iteration counts and RNG streams. Public checkpoint.pt explicitly starts new ground episodes after a completed PPO update; unfinished episodes are counted as aborted and excluded from success statistics. The saved canonical root/joints/targets, task buffers and history are restored exactly. Diagnostic model_i files retain arbitrary states for inspection or weight initialization and are rejected for full resume.

Earlier in-contact physical restores exceeded the unchanged continuation tolerances because PhysX solver caches are inaccessible. Those failures remain recorded. The corrected public checkpoint protocol avoids promising arbitrary mid-contact replay. Exact initial observation/action and RNG checks precede five steps with identical recorded actions under the original tolerances; policy sensitivity during replay is also reported. No recorded reference actions are used in PPO training, and no bitwise physical replay is claimed.

A controlled SIGTERM was sent through the owned GPU guard after two updates. The native loop completed its current update, saved atomically and exited; a separate process loaded that interrupted checkpoint and continued. Stale PID protection compares Linux boot ID, process start tick, UID, command hash, cwd and run directory. Missing/stale identity is never permission to kill another process.

Frozen development panels each contain 200 normal ground initializations. Seeds, perturbation ranges, recovery/jump criteria and future G10 holdout generation rules are in evaluation_manifest.json and configs/evaluation_protocol_v2.json. No G10 results were accessed. The maximum recovery joint speed (1 rad/s) is now explicit alongside the original roll/pitch, root speed, angular speed and continuous .8s window.

Raw native data/checkpoints/logs/source snapshots are under reports/G03/native_20261022T041355_436993. Earlier reduced NumPy and incomplete native evidence remains invalidated. This proves engineering readiness only; G04's old root-height and accumulated-recovery success calculation still needs replacement before corrected task training/evaluation. No jump/contact/smash success rate is claimed here.
