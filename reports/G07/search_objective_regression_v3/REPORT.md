# G07 v3 搜索目标回归修复

这是 `ec32f75` 后的 CPU 代码修复，没有新的原生机器人轨迹、学习成绩或 GPU 用量。新的 GPU0 工作时间窗及 GPU-hours 上限仍待用户回复；原时间窗已过期。

检查发现四个会影响后续真实搜索的问题，并完成修复：

1. 未得到真实有效扣杀时，旧辅助排序只看前向速度和预测越网余量，可能偏向向上挑球。现在辅助分数联合计算攻击速度/向下方向、有限网体净空、横向范围和第一次落点约束；真实有序完整成功、落点、越网仍排在所有预测分数之前。预测不写入真实成功标志。
2. 球已首次有效落地后，如果又与球拍接触，最终完整成功会失效，但旧排序仍可能读取之前锁存的落点并给出完整成功优先级。新排序检查最终事件有效性、接触次数、有效面、空中接触、实际出球和数值故障。
3. 出球预测曾混用了首次接触位置和最后一个接触力帧的速度。新记录保留同一力帧的位置、速度和时间；分离确认同时要求无接触力及超过几何分离滞回，避免短暂失力被当作已分离。
4. 只存当前最佳候选会丢掉有效越网但尚未恢复的其他动作。搜索现在单独保留这些候选的完整关节节点和时间参数，后续可以重放并解决恢复。探索距离只在命令击球时间窗、球首次落地前累计。

CPU 反例见 `coupled_ranking.json`：球心 [1.4,0,1.65] m，向下出球 [7.5,0,−3] m/s 的保守网后缘净空约 4.54 cm，首次落点 x≈3.961 m；向上出球 [7.5,0,+3] m/s 的净空更大，约 15.34 cm，却落到 x≈7.985 m。前者耦合预测违约分数为 0，后者约 2.993，排序已正确偏向前者；两个案例的真实成功标志均保持 false，因为未发生真实机器人碰撞。

89 项 CPU 物理/几何/时序/预算回归通过，原始结果为 `cpu_tests.xml`。新原生记录器和搜索入口通过语法检查，但未启动 Isaac，不能用这些检查代替 native 验证。源文件哈希见 `source_sha256.json`。
