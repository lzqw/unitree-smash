# Go2 + PiPER 腾空扣球落地辅助：MPC/VHSIP 实验汇总

更新时间：2026-11-06（北京时间）  
分支：`g07-contact-flight-recovery-v5-20261027`  
最新代码提交：`1a9946a`

## 1. 目标与评估范围

本阶段目标是验证控制器能否在保持已经完成的击球结果的同时，降低落地后的非足部触地和稳定窗口失败。所有主要对照都使用同一冻结策略、同一 128 个 TRAIN 条件、同一 5 m/s `complete5` 判定和同一 Go2+PiPER+球拍资产。评估仍保留原有基础控制器和持久恢复辅助，因此不能称为完全独立的全身 RL。

当前固定策略基线为：

| 指标 | 基线 |
|---|---:|
| 完整成功 `complete5` | **27/128** |
| 合格空中触球 | 74 |
| 条件恢复 | 34 |
| 实际球拍接触 | 110 |
| 越网 | 71 |
| 目标落点 | 64 |
| 数值故障 | 0 |

恢复审计显示，满足除恢复外全部任务条件的失败主要是 26 个回合；这 26 个回合全部先完成足端着地，其中 22 个随后出现非足部触地，另有 4 个没有形成稳定窗口。非足部触地通常发生在首次足端着地后 0.333–3.707 秒，中位数约 1.935 秒。问题因此从“能否第一次碰地”转为“碰地后能否持续支撑”。

## 2. 实现过的控制路线

### 2.1 固定接触全身支撑 QP

`landing_support_mpc_v1/v2/v3.py` 使用 Pinocchio 全身动力学、足端接触约束、摩擦锥、即时 position-PD 力矩边界和短 horizon 顺序 QP。v2/v3 增加了支撑裕度、单足 touchdown recovery、连续 COM 参考、软足端任务和非足部净空任务。

它可以求解局部支撑动作，但不建模碰撞冲量、接触创建、PhysX 隐式积分、电机惯量和摩擦，因此“QP solved”只表示模型内一阶动作可行。

### 2.2 原生 Isaac 状态适配

新增 `LoadedPinocchioModelV1.state_from_native()`，直接读取：

- Isaac root link 位姿；
- COM 线速度和角速度，并换算到 root link/body 约定；
- 18 个关节位置和速度；
- 实测足端接触滞回。

评估器在每个 tick 把真实 Isaac 环境交给 MPC，并在记录中写入 `state_source=native_sim_state`。这排除了公开观测反解造成的主要状态误差，但没有改变最终任务成绩。

### 2.3 上游 Reactive Landing Controller / VHSIP 路线

参考上游 [Reactive Landing Controller](https://github.com/iit-DLSLab/reactive_landing_controller) 的结构，将 `ReactiveLandingV1` 扩展为读取原生状态的 VHSIP/足端参考。上游方法的核心是：下降阶段用 SLIP/VHSIP 质心捕获参考，足端 IK 生成落脚目标，触地后继续跟踪落地轨迹；它并不是当前这种固定接触全身 QP 的直接替代品。

本地还加入了 touchdown 支撑锚点锁存：首次真实足端接触后允许新足加入，但不因瞬时接触力阈值波动清除已经建立的落脚参考。

## 3. 实验结果

### 3.1 全身 QP 系列

| 实验 | `complete5` | 空中触球 | 条件恢复 | 实际球拍接触 | MPC 诊断摘要 |
|---|---:|---:|---:|---:|---|
| 固定策略基线 | 27 | 74 | 34 | 110 | 无额外 MPC |
| 历史 touchdown v3 `_04` | 28 | 74 | 35 | 110 | 历史单次提升，后续修正版本未复现，不能作为当前结论 |
| 非足部净空 `_05` | 27 | 74 | 34 | 110 | 270 个 horizon 接受；83 solver、101 约束拒绝；预测接触 0 |
| 连续参考＋保留机械臂 | 27 | 74 | 34 | 110 | 0 个完整 horizon 接受；1188 solver failure，主要为 primal infeasible |
| 连续参考＋释放机械臂 | 27 | 74 | 34 | 110 | 349 个 horizon 接受；solver failure 降至 60，但任务无提升 |
| 放宽触地阈值 | 27 | 74 | 34 | 110 | 307 个 horizon 接受；预测接触仍为 0 |
| **原生 Isaac 状态** | **27** | **74** | **34** | **110** | 343 个 horizon 接受；111 solver、98 约束拒绝 |
| **原生状态＋预测触地** | **27** | **74** | **34** | **110** | 291 个 horizon 接受；预测接触仍为 0 |

原生状态两组的目标落点均为 63，数值故障均为 0。它们说明真实状态适配提高了诊断可信度，但没有改变物理落地结果；把 touchdown 高度容差放宽到 6 cm、下降速度上限放宽到 5 m/s 也没有生成任何可接受的预测接触模式。

### 3.2 原生 VHSIP/足端参考系列

| 实验 | `complete5` | 空中触球 | 条件恢复 | 越网 | 目标落点 |
|---|---:|---:|---:|---:|---:|
| 原生 VHSIP，26 个恢复失败案例 | 23 | 74 | 33 | 72 | 62 |
| 原生 VHSIP＋touchdown 支撑锁存 | 23 | 74 | 33 | 72 | 62 |

两次实验都没有新增完整成功，并且相对 27/128 基线丢失 4 个旧成功。说明“直接把 VHSIP 捕获点转成现有 position-PD 关节目标”不足以形成稳定落地；需要真正的 touchdown 阶段状态机、落地后参考持续执行和执行误差闭环。

## 4. MPC 求解失败的分类

当前原生状态 QP 记录中，失败不能简单统称为“求解器无解”：

1. **真正数值/可行性失败**：少量 `primal infeasible` 或 `maximum iterations reached`。
2. **OSQP 返回 solved 但原始物理约束残差超限**：典型动力学残差约 `9e-7`，但所有线性约束最大残差约 `1.96e-3`，高于当前 `3e-4` 验收阈值。
3. **局部 horizon 可行、终端支撑裕度不满足**：短期动作能算出来，但 8 步后 COM 仍无法进入要求的支撑区域。
4. **模型与 PhysX 执行不一致**：没有碰撞冲量、接触创建、隐式 PD 延迟、电机惯量和摩擦，导致模型内计划不能把真实状态带入预测终点。

因此，MPC 是“部分状态可以求解”，而不是“完全不可求解”。问题主要在接触模式和执行接口，而不是继续把 OSQP 迭代数调大。

## 5. 当前判断

- 固定接触全身 QP 暂时没有改善完整成功率；
- 原生状态接入是必要修正，但不是单独的性能突破；
- 放宽预测触地阈值没有解决接触创建问题；
- VHSIP/足端参考在当前 position-PD 接口上没有直接收益，且锁存 touchdown 参考后仍为 23/128；
- 上游方法值得借鉴的是阶段化落地结构，而不是直接复制其 Go1 控制器或把 SLIP 参考当成完整 MPC。

## 6. 下一步实施顺序

1. **真实 touchdown 事件驱动的落地状态机**：首次足端接触后锁存参考，持续执行固定缓冲窗口；后续足端接触发生后重新构建支撑模式。
2. **执行器回放模型**：把 position-PD、限幅、限速和一个控制周期延迟放进预测；用真实关节状态与目标误差校正模型。
3. **有限接触模式 QP**：分别处理一足、两足、三足、四足模式，只在真实接触确认后切换，不在 horizon 内凭几何距离虚构冲量。
4. **记录闭环证据**：首次 touchdown 后足端目标/实际位置、关节误差、机身角速度、非足部首次接触部件和时间。
5. **再做 JAX/GPU**：先把固定维度 VHSIP、FK/Jacobian 和有限模式预测移植到 JAX；CPU OSQP 外包不会带来 GPU 加速。之后再做批量求解或策略蒸馏。

本阶段没有把大体积仿真日志、视频和 checkpoint 上传 GitHub；完整结果仍保存在服务器报告目录，GitHub 只提交代码、报告和可复现实验说明。
