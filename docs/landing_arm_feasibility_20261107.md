# 恢复QP约束冲突：固定机械臂目标限制了部分早期恢复，但解除它尚未改善完整预测

日期：2026-11-07。以下新增结果均为已完成原生轨迹上的CPU分析与候选回放，不是新原生成功率。GPU0的主动集区间控制试验继续使用原输入，未在运行中换控制器。

## 当前保留结果

学生基线27/128；持续反馈控制辅助35/128，已由两个独立进程重复确认，保留原27并救回8例。控制仍只对预先指定的26个失败案例启用。首版学生学习头关闭额外MPC后13/128，已拒绝。参见[完整状态报告](native_recovery_teacher_off13_20261107.md)。

本轮回答的是：此前30个被拒QP中，16个已由更合适的求解器解决；另外14个在原模型内确实不可行，究竟冲突在哪里？

## 13个状态的冲突涉及硬性保留机械臂命令

对同一14个状态重建完整16子步区间约束，以HiGHS确认不可行。然后仅作离线诊断，分别删除一个约束族，检查是否恢复线性可行性：

| 诊断中暂时删除的约束族 | 恢复可行的状态数 |
|---|---:|
| 完全保留学生机械臂位置目标的等式 | 13/14 |
| 关节速度限制 | 13/14 |
| 电机力矩限制 | 3/14 |
| 关节位置限制 | 1/14 |
| 摩擦、法向力、原生命令边界、根高度（分别删除） | 各0/14 |

这些是同一批样本的不同诊断，不能相加。约束族删除不是可执行控制方案；特别是不会把删除速度或力矩限制的结果用于仿真。

随后实际求解的候选**只取消“必须完全复制学生臂部目标”这一附加等式**，仍保留原关节位置、机械臂5 rad/s物理速度、100 Nm力矩、实际前一命令约束、10 rad/s目标变化率及足地约束。13个状态均通过独立动力学与全区间约束检查。相对原学生参考，臂部最大关节修正约0.082–0.140 rad；此差值不等于相对上一实际命令的变化率。

这些样本发生在TRAIN70/71/77的3.00秒、TRAIN1/3/8/20/30/38/61/87/90的3.20秒，以及TRAIN42的4.60秒。它们说明：一部分拒绝来自“原臂部目标与要求的速度/力矩约束不能同时满足”，不是摩擦阈值单独造成，也不是所有状态都没有恢复动作。不能据此断言这些候选执行后一定稳定。

## 已实现有限臂部配合，不改硬件限制

[候选实现](../scripts/landing_arm_feasibility_mpc_v1.py)的步骤是：

1. 首先按原方案完全保留臂部目标求解。
2. 仅当求解器明确报告`primal infeasible`，才允许臂部目标在原边界内变化。数值错误、迭代失败和残差超限不会自动触发这一分支。
3. 新解仍须通过原全部物理与执行约束；学生参考仍进入姿态软目标。
4. 两次尝试使用同一个参考状态，参考时钟只推进一次；失败尝试不污染后续控制记忆。

它不是每步任意重写机械臂，也没有通过混合一个未经验证的学生动作破坏QP输出。但目前也不宣称找到了全局最小纠正或完整恢复轨迹。

12项实际数值测试通过，其中新增检查覆盖：可行时动作与原方案逐元素一致；固定臂目标不可行时，有限修正通过独立16子步动力学验证；重试不重复推进参考；原根高度违规仍被拒绝。

## 完整回放给出了必要的反面结果

在35/128来源轨迹的同一479个记录状态上：

| 模型检查 | 原主动集区间QP | 加有限臂部配合 |
|---|---:|---:|
| 首步通过 | 270 | 283 |
| 完整40阶段及终端检查通过 | 187 | **187** |
| 原先通过、后来丢失 | — | 0 |

在救回8例的196个采样状态中，首步通过由193增至196；但这仍是记录状态回放，不能当作196次救援。

新增13个首步可行状态中，12个在后续第7–34预测阶段再次失败；TRAIN8的3.20秒样本推进完40阶段，但终端支撑裕度未通过。**因此这个修正只消除部分眼前冲突，尚未增加完整预测的可恢复区域。**它没有被插入正在运行的GPU实验，也没有仅凭首步数字就排队替换基线。

## 剩余不可行状态接近关节限位

TRAIN42、3.60秒：右前髋角为1.046530 rad，上限1.047200 rad，只剩0.000670 rad余量，且仍以约1.503 rad/s朝上限运动。取消固定臂目标后仍不可行。删除关节位置约束才能使这组线性问题变可行。

这提示需要更早制动，或更准确地处理真实关节限位反作用及接触变化。当前预测采用冻结接触与未饱和PD分支，不能从这一次求解推导硬件物理上绝对不可恢复。不能用放宽关节限位解决它。

## 预测与PhysX响应：终于有同命令的直接比较

另取同一479个记录状态，用实际最终下发命令预测10 ms后的状态，再与相邻原生记录比较，包含28个观测接触标志变化样本。没有事后选择另一条命令。

在其中243个原控制器实际应用首步的样本上，以下为每个样本最大关节误差的中位数，机身角速度项为范数误差中位数：

| 一步预测误差 | 原初始力矩近似 | 16子步隐式PD |
|---|---:|---:|
| 臂部位置 | 0.000427 rad | 0.000065 rad |
| 腿部位置 | 0.000501 rad | 0.000428 rad |
| 臂部速度 | 0.09227 rad/s | 0.00438 rad/s |
| 腿部速度 | 0.08699 rad/s | 0.04724 rad/s |
| 机身角速度 | 0.01431 rad/s | 0.00425 rad/s |

因此，不能再只说“加入回放”而没有误差证据；现在有同命令、同相邻时间间隔的直接支持。但全部479样本上的误差明显更大，分布尾部、接触切换、失败状态与长期累积仍需处理。160子步也未在这些中位数上带来普遍显著改善，不宜把下一步简单定义成增加积分步数。

一步精度不等于0.4秒预测精度，更不等于数秒持续恢复保证。当前结构仍是逐步QP前推，并没有根据终端失败联合重优化整段控制序列。

## 接下来据什么决定

先完成正在运行的主动集区间控制原生试验，再对照实际救回、丢失和预测误差。有限臂部配合保留为已测试候选，不把CPU首步改善称为原生收益。若完整恢复仍无提高，应优先解决后续支撑/接触计划与终端目标的协调，而不是继续仅扫描同一组增益或接触阈值。
