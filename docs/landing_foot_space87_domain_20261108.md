# 完整恢复候选的适用范围与预测检查

2026年11月8日。本轮继续检验TRAIN87完整模型恢复候选，没有替换原27/128学生基线，也没有开展新的PPO更新。

## 同一恢复方案能否直接覆盖其他失败？

原26个球侧合格但恢复失败案例中，24个在2.8秒满足本轮首次回合、已击球且腾空查询条件；TRAIN12、TRAIN58不满足，未强行施加这套查询。初态、速度和上一条实际命令来自已通过被动隔离审计的原生状态库，只对参考做水平位置与偏航对齐，没有调整实测初态。

使用同一组脚位、全身过渡和反馈参数，不为各案例重新搜索。每个控制步160个物理子步，预测至原8秒回合结束。

- TRAIN87完成520步，末端连续稳定2.58秒；独立重放与原名义解的状态、速度、接触、目标逐项相同。
- 其余23个在16—85步后被路径检查拒绝，即接管后0.16—0.85秒。
- 21个出现模型非足部触地：首次涉及Head_lower 12个、RR_calf 7个、FL_hip 1个、RL_calf 1个。
- 10个有关节位置越界，其中8个与非足部触地同时出现，另2个只有关节越界。因此这些计数不能相加当作不同回合。

这不是“控制方法只有1/24成功率”的泛化结论，也不是其他状态不可恢复的证明。它说明当前针对TRAIN87优化的一条局部反馈轨迹，尚不能直接迁移到其他记录初态。后续MPC需要根据实际状态重新选择脚位、过渡和恢复动作，而不是统一播放同一模板。模型拒绝的轨迹不进入正向专家数据。

## 新增实际单步预测检查

新增`audit_native_feedback_prediction_v1.py`：每次从真实记录的q、v和命令历史出发，使用当步最终下发目标预测10毫秒，再与下一条实际状态比较。前0.5秒逐步检查，后续每0.1秒检查；时间点预先固定，不按误差挑样本。检查真实命令历史连续、数据哈希和首次回合连续时钟。

已在此前TRAIN3原生反馈记录上实际运行97个区间，97个均完成预测。它是已有原生轨迹的CPU诊断，不是新一次GPU救援；该运行原有的未介入案例隔离审计失败仍保留为失败。
