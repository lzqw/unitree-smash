# 从实际失稳前状态重新规划完整恢复动作

2026年11月9日。继续纯控制落地验证，不进行RL、BC或教师蒸馏；原生GPU作业与串行对照继续运行。本轮新增的是实际状态出发的整段动作优化，尚不能称为部署完成的实时MPC。

## 为什么开展这项计算

上一轮检查表明，TRAIN64、118在真实参考结束状态上继续运行旧/新支撑反馈都会失败；单纯保存稳定站姿的控制目标无法处理尚未稳定的状态。另一方面，TRAIN12、58已经进入支撑阶段，仍发生晚期失稳，需要判断在失稳前是否存在另一条可执行动作。

本轮取四个记录完整的原生状态：TRAIN64第340步、TRAIN118第338步、TRAIN12第550步、TRAIN58第470步。它们均已经因果确认球分离并由恢复控制拥有最终命令，取样前没有落地段非足部受力记录。选择这些编号仅用于安排诊断，优化器的目标和约束不依赖TRAIN编号。

## 实际实现的搜索

- 状态包含实际全身构型、速度、上一实际命令、足地力观测及阶段记忆，不使用之后的原生动作或状态作为搜索初值或评分。
- 同时优化两秒内全部18关节的八个命令控制点，第一步命令也可调整；原关节范围内生成平滑目标，再通过原PD、力矩与实际速度限制传播。
- 以预测轨迹物理可行为优先，再考虑末尾连续稳定和姿态、速度收敛；不要求每个过渡时刻立即站直，不增加电机能力。
- 每个候选使用整机耦合动力学、接触和已建模的碰撞约束。粗搜索每控制步16子步，前三个候选再以160子步复核。没有获得完整模型路径的候选不自动进入后段执行检查。
- 优化采用不同实际候选作为采样中心，避免把相互冲突的接触动作逐点平均；没有固定旧腿部或机械臂命令。

这是原生记录上的CPU模型计算，不是将Isaac机器人传送到中途状态。模型仍不能完整复刻PhysX；模型接受和优化收敛不能作为原生成功或正确示范标签。

## 必须接上的后半段

已建立自动后续任务：搜索正常完成后，将通过细模型检查的轨迹交给现有全身预测命令选择器逐步执行。每步读取模型当前状态进行反馈，参考结束后继续缓冲/支撑控制到原8秒末。没有只保存两秒末的一帧，也没有把最后一个目标一直保持作为验收。

后续检查分别记录：参考跟踪阶段是否偏离、何时发生身体碰地、是否触发未认证回退、最终连续稳定是否保持。即使某条两秒轨迹通过，也必须单独查看这个完整反馈结果。

正式原生收益仍需从地面执行原击球前缀后验证。本轮中途状态模型计算不计入完整成功率，不替代当前全TRAIN128物理评估。

在同一个TRAIN118实际状态上，原支撑反馈曾在模型第394步失败，即约0.56秒后失败；新路径至少说明模型内存在另一种短时恢复动作。它不证明硬件已实际完成该动作，也不能把收益全部归因于某个单一关节。
