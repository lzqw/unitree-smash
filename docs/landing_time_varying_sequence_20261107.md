# 沿名义轨迹更新动力学的整段恢复优化

2026-11-07。新增时变局部模型和主动集求解对照；仍为CPU离线候选生成，未接入Isaac，没有新增原生成功成绩。

## 实际改动

从当前实际报警状态出发，用现有控制器生成40步名义轨迹。仅当40步物理约束均通过时，才将其用于局部优化；终端恢复要求可以尚未通过。每10 ms更新一次完整负载质量矩阵、动力学偏置和接触雅可比，沿名义接触序列传播，而不是将起始姿态冻结0.4秒。

9个全身命令节点表示对名义40步命令的增量，零增量保留原轨迹。局部增量范围±0.1 rad，原力矩、速度、关节限位、摩擦、命令限速及全部子步约束不变。原控制器无法提供完整约束通过的轨迹时，明确记为缺少初值，没有随意补齐后半段。

这不是完整非线性轨迹优化：当前没有包含动力学对候选构型变化的完整导数，也未搜索新的抬脚/落脚序列。几何只采用局部近似，必须再做整段非线性重放。

## 实测结果

对同一60个首次报警状态查询，4个CPU进程；使用已安装的`quadprog`主动集后端，整项作业设置600秒外部进程保护。该后端单次调用没有可抢占的20秒硬截止，代码将此限制显式记录，不能声称适合实时控制。

| 项目 | 数量 |
|---|---:|
| 查询状态 | 60 |
| 缺少完整约束通过的名义轨迹 | 32 |
| 可建立局部优化的名义轨迹 | 28 |
| 线性QP求解通过 | **28** |
| 非零更新通过整段非线性复核 | **0** |
| 仅退回原计划后通过 | **1，TRAIN2** |
| 新增模型内完整恢复计划 | **0** |

零增量对原轨迹的最大约束违反约9.21e-12，支持坐标和命令增量接口一致；这不证明非零变化时的预测准确。原22个目标非足部触地失败没有获得新的完整计划。

首轮OSQP在有初值的TRAIN2/3仍返回低精度解；同样的局部问题换用主动集后可求解。全部60例的最终查询耗时相加约100.06秒，这不是并行墙钟时间。改善的是数值求解，不能当作实际恢复收益。

## 为什么没有把线性解送进教师

对线性提案进行步长1、1/2、1/4、1/8、1/16、1/32、0的整段非线性复核，保留实际命令历史和原物理/终端判定。这是优化器内部的候选检查，不是在执行时任意混合危险学生与教师动作。

本轮所有非零候选仍在中途被物理约束拒绝，主要涉及摩擦与关节速度等。零步长恢复了名义轨迹：其中27例仍未达到终端恢复条件，TRAIN2原本已有完整模型计划，因此唯一通过不算新增。

这说明“沿名义轨迹更新M/h/J”尚未让模型正确描述优化增量后的全过程。后续要检查模型对命令变化的灵敏度、约束线性化和未来接触规划，不能仅把求解器更换后的28个`solved`作为可用恢复教师。
