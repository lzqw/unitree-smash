# 将局部修复接入连续MPC

2026-11-07，北京时间。[快照与来源哈希](landing_recursive_mpc_v2_20261107.json)。学生基线仍为27/128，本轮尚无完整原生恢复或新学生学习成绩。

## 改了什么

上一轮已经证明：从保存的失败状态出发，局部有限差分与QP方向搜索能找到CEM遗漏的可行后续序列。本轮将这一过程接入可重复调用的规划器，不再要求人工单独启动每次修复。

新流程为：

```text
当前实测状态＋实际上一帧命令
    → 移位原计划并检查
    → 必要时局部约束修复
    → 完整非线性重放＋独立工作进程复核
    → 通过后输出序列；未通过才进入有界CEM
    → 仍未通过则返回失败，不输出候选动作
```

整机、摩擦接触、PD响应、硬件边界、非足部地面约束和末端检查沿用同一预测模型。QP松弛只用于提出修复方向，不构成验收。每次读取新的q、v和命令历史；仅复用命令初值，不复用旧预测状态作为当前状态。

默认采用保留前13个指令的后段修复；若原候选已经在早期路径违反约束，允许修正基函数从第0步开始。初值和最终输出都经过原命令限制检查。失败修复只能用作后续搜索初值，不能直接下发或作为正向学习标签。

求解仍是离线/同步仿真教师实现，不是100 Hz实时控制器。每次声明600秒预算，工作进程有响应截止时间，外部进程仍需硬时间保护；没有将这些设置称为严格单次实时截止保证。

## 已获得的证据

上一版在模型执行100毫秒后无法找到通过约束的后续序列。新版从相同初态重跑：

| 重规划时刻 | 新版结果 | 求解耗时 |
|---|---|---:|
| 初始查询 | 通过 | 7.89秒 |
| 已执行100毫秒 | 修复后通过 | 299.65秒 |

已独立重放实际用于模型推进的前缀，累计推进20/340步；后续检查仍在运行。除初态来自原生记录外，后续状态均为模型预测。

**这证明新版跨过了此前的一次求解失败，不证明全部剩余时域可行，也不证明连续0.8秒稳定。** 初始候选只有30毫秒连续符合稳定运动学条件的限制仍需通过后续控制解决。

3项故障注入检查通过：独立复核拒绝、上一帧命令历史错误、求解预算已耗尽时，都不能输出可执行候选。它们验证接入语义，不代替物理执行。原生接入和生成入口通过语法检查。
