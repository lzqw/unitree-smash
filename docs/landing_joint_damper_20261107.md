# 提前制动候选：完整预测增加3个状态，同时拒绝7个原可行首步

2026-11-07。本报告是**479个记录状态的CPU配对回放**，不是新原生成功率。保留学生27/128、控制辅助35/128；GPU主评测继续使用固定输入。本次没有更换主控制器或任务限制。

## 为什么做这一项

[上一轮定位](landing_later_prediction_failures_20261107.md)发现：6个新首步可行状态在后续预测中遭遇关节位置约束冲突。其中多例髋关节到达限位时，仍以数rad/s朝限位方向运动。逐步检查位置不越限，不能保证随后有足够余量停下。

参考实现中，Pink的[ConfigurationLimit](https://github.com/pink-kinematics/pink/blob/main/pink/limits/configuration_limit.py)在剩余关节位移上施加速度/位移限制；其[AccelerationLimit](https://github.com/pink-kinematics/pink/blob/main/pink/limits/acceleration_limit.py)还显式考虑制动距离。这里只借鉴限制方式，未安装或搬用Pink的运动学求解器，也没有把其中指定的加速度能力当成Go2＋PiPER的能力。

## 实际实现

在原带负载动力学、实际前一命令及隐式PD区间QP上，加入：

\[
-k(q_j-q_{j,\min})\leq v_j\leq k(q_{j,\max}-q_j),\qquad k=20\;\mathrm{s}^{-1}。
\]

约束作用于10 ms控制区间内的全部16个隐式积分子步、全部18个关节。位置和速度均由同一个持有不变的关节目标预测得到，约束可以凝聚到原18个命令变量上。增加288条不等式，没有增加决策变量。

`k=20`是本次声明的50 ms尺度工程候选，不是辨识得到的电机制动能力，也没有通过参数扫描挑选成绩。原关节位置、速度、力矩、摩擦、法向力、根高度和实际目标变化率约束全部保留。

候选继续采用“能保留学生臂部命令时保留；该附加等式不可行时允许原边界内的臂部配合”。重试不会把参考时钟推进两次。

此限制是一种保守速度包络，**不是带负载动力学的可恢复域证明**。当前速度已经超出包络时，即使存在其他可恢复动作，它也可能拒绝。代码没有把拒绝结果标为安全，也没有自动放宽硬件限制。

当前运行核心文件未修改。新[控制候选](../scripts/landing_joint_damper_mpc_v1.py)通过局部求解器适配器增加约束，避免修改已经固定源码的GPU队列。

## 决策与下一步

保留实现和结果，**不替换35/128控制基线，不立即把该约束接入GPU主线，也不开展连续增益扫描**。先完成正在运行的区间控制与事件加权学习评测。

后续规划应让完整恢复目标影响前面的命令，考虑支撑和关节制动余量的共同可行性。若采用速度包络，需要处理已在包络外的真实状态；不能简单把这些状态全部交还给未验证的旧动作。当前仍是逐步QP前推，不宣称已经实现联合优化整段控制序列的MPC。
