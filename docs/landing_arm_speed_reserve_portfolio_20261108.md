# 机械臂恢复速度余量与反馈候选MPC

本轮取得模型层面的具体改进：原来无法由持续反馈恢复的TRAIN3第473步实际状态，现在能完成剩余327步模型恢复；将新旧反馈作为候选，三个实际查询均通过原MPC约束。**没有新增原生成功或学生收益，学生系统仍为27/128。** 数据、源文件哈希、进程快照见[紧凑JSON](landing_arm_speed_reserve_portfolio_20261108.json)。

## 定位到的限制

当前持续反馈原本只对腿部进行状态修正，机械臂主要跟随原参考。该参考中机械臂第2关节峰值速度为4.944387 rad/s，距离实际5 rad/s限制约0.0556 rad/s；25个参考采样点超过4.5 rad/s。实际中途状态偏离名义轨迹后，继续跟踪这条近边界参考容易缺少余量。

这是本次模型查询上的证据，不是对全部26个恢复失败的唯一归因。三个查询来自同一TRAIN3原生轨迹，不能当成三个独立来球或泛化验证。原生V1的TRAIN125隔离审计仍失败，本轮只使用其中实际记录的TRAIN3状态，不提升整体审计状态。

## 两项不同的控制改动

第一项在原有−0.006 rad短时机械臂修正之外，增加当前机械臂速度相对参考的反馈：

`Δq_arm = clip(−D × (v_actual − v_reference) / Kp, −0.02, 0.02)`。

这里修改的是位置目标请求，没有修改物理PD参数、力矩/速度限制。腿部原反馈、关节限制和机械臂目标限速继续保留。0.02 rad只约束新增速度反馈，不能当成所有历史修正的总幅度。

第二项将该速度反馈使用的机械臂参考限制在±4.5 rad/s，给恢复动作留出速度余量；基础腿部轨迹和原名义命令不被直接截断，实际预测速度仍按原5 rad/s硬件限制检查。这是一项恢复控制候选，不是更改任务或放宽验收。

## 完整剩余轨迹结果

低强度D=0.5、1在16子步下没有救回第473步状态。即使D=4、采用160子步，原速度参考仍在第488步超限0.011487 rad/s。因此没有把“超量减少”记为成功。

加入4.5 rad/s参考余量后，160子步验证如下：

| 原生查询步 | 剩余控制步 | 全程路径约束 | 最长模型稳定窗口 |
|---:|---:|---|---:|
| 460 | 340 | 通过 | 1.02秒 |
| 473 | 327 | 通过 | 1.01秒 |
| 478 | 322 | 通过 | 1.01秒 |

所有试验保留实际q/v、接触和上一条下发命令，使用原回合时钟持续到第800步。没有重新归零相位或传送原生机器人。检查包含整段非足部净空、关节位置/速度和力矩，但模型窗口不包含原生受力及同次飞行关联判定，**不等于正式恢复通过**。

## 为什么不能直接用新反馈替换旧反馈

将新反馈单独用作80步MPC初值时：

- 第460步：预测末端roll约−0.2722 rad，超过原15°要求；新初值被拒绝，原计划仍可接受。
- 第473步：新反馈通过路径与终端检查，约13.19秒求解通过。
- 第478步：预测末端仅两足支撑，裕度约−0.03497m；新初值被拒绝，随后修复在预算内未找到解。

第478步的新反馈虽然在更长模型延续中恢复，但不能冒充满足现有80步终端要求。该次失败继续保留，也没有调整支撑裕度或倾角阈值。

因此新增`FrictionalFeedbackPortfolioV4`：固定顺序尝试原机械臂修正反馈、预留速度余量反馈；每个候选都从当前测量状态和命令历史生成完整80步轨迹，并独立复核原约束。首个通过者交给原V2再次验收；都不通过则保留原平移计划和修复流程。候选选择不读取未来结果，也不按案例编号选动作。

| 查询步 | 实际选中的反馈初值 | 最终MPC接受 | 整次求解墙钟 |
|---:|---|---|---:|
| 460 | 原机械臂修正反馈 | 是 | 14.79秒 |
| 473 | 预留速度余量反馈 | 是 | 13.81秒 |
| 478 | 原机械臂修正反馈 | 是 | 14.82秒 |

这仍不是实时MPC，也不是递归可行性证明。它说明不同反馈在不同当前状态下各有有效范围，使用统一约束验证候选比一律替换更合适。
