# 落地控制：纠正命令限速的参照对象（2026-11-07）

当前已完成成绩仍是27/128。本文报告新的执行接口修正，不宣称已经提高落地成功率。

## 原始执行接口核查

`quadsmash/tasks/stand/full_racket_env_v4.py::_pre_physics_step` 将归一化动作转换成原关节范围内的绝对目标，随后交给原隐式PD执行器。它没有把目标限定在“实测角 ± 物理速度上限 × dt”。

`quadsmash/control/full_racket_arm_target_rate_v4.py` 的软件限速使用上一条目标角，只有初始化或时钟重置时才用实测角初始化。当前冻结检查点的 `residual_arm_target_rate_rad_s=10.0`；这与执行器的5 rad/s实际关节速度上限是不同参数。

原执行器参数保持：腿部23.5 N·m、30 rad/s、Kp=25、Kd=0.5；机械臂100 N·m、5 rad/s、Kp=80、Kd=4。场地、资产、碰撞、成功标准不变。

## 此前MPC额外限制了什么

此前MPC将目标裁剪为 `q_measured ± velocity_limit * 0.01`，QP也采用了相应力矩区间。它确实让内部预测与新增裁剪更一致，但该裁剪并非原执行接口的要求。

以零关节速度下的瞬时PD模型为例，腿部目标误差不超过0.3 rad，弹性项因此不超过7.5 N·m；机械臂误差不超过0.05 rad，弹性项不超过4 N·m。这比原执行器力矩范围更窄。实际运动时还存在阻尼和隐式求解，不能把这些数值直接当成实测力矩。

这是控制权限的人工限制，可能使持续承载目标无法实现；目前尚未量化它对完整失败的贡献。

## 新实现

- `CommandHistoryPDInterface`：腿目标保留原关节范围；机械臂目标按上一条**最终下发命令**及检查点声明的软件速率限幅。
- QP继续约束原力矩、预测关节位置和预测实际速度；PD饱和正确进入可实现力矩区间。
- `CommandHistorySupportQP` 使用上述目标区间求解并独立检查残差。
- `LandingCommandHistoryMPCV1` 将最终命令历史随预测状态推进；终端重放使用同一历史，按环境/回合隔离。
- 原生评估从 `env.targets` 读取上一条实际下发目标。教师求解失败时，学生回退命令也通过同一机械臂命令历史，避免交接跳变。
- 新入口 `--landing-mpc-command-history-interface` 明确启用；旧模式保留，便于复现。

这没有删除物理速度限制，也没有加入外力或修改质量。它纠正了软件目标限速的参照对象。当前求解器仍为顺序支撑QP滚动，并非整段控制序列联合最优化。
