## 新发现：原生时间导致参考重复一帧

原生时钟来自`episode_length_buf * step_dt`，以float32保存。控制器原先使用：

```python
index = floor(elapsed / 0.01 + 1e-6)
```

例如实际第2步的时间差是`0.019999980926513672`。除以0.01后仍略小于2，原修正量不足，索引成为1。于是参考可能重复上一帧，随后跳过一帧。参考结束条件也受同一舍入影响。

模型测试使用双精度时间，未重现这个执行差异。独立读取已完成原生记录后，31个实际匹配案例共发现**1142次参考索引与整数控制步不一致**。这不是浮点状态比较造成的虚警：记录中的参考索引确实指向前一帧。

新的v12在声明的100Hz控制网格上使用最近整数步，并由整数步决定参考结束和最后100毫秒的参考权重；明显偏离该控制网格的调用会报错。没有改动控制周期、执行器或物理状态。

已执行验证：

- 对录制时钟分别检查60、160、320步参考，共113778项。旧逻辑有27945项索引差异，新逻辑0项；这是多种参考长度的测试组合计数，不等于实际执行中出现27945次错误。
- float32及双精度、多种起始时间的合成检查共24030项通过。
- 新控制器的31条参考、158项真实求解与命令仲裁入口检查通过。

这些是索引和接口证据，不是落地性能证据。不能提前把全部碰地归因于这一错误。

原生参考追踪审计也改用记录中的整数控制步重建期望轨迹，避免审计程序复制同一向下取整问题。逐案例结果见配套JSON。

## 作业处理与当前实验

已经启动、仍沿用旧时序逻辑的v11长参考试验通过本项目GPU守护进程主动停止，保留全部记录。累计耗时约0.015 GPU小时；没有完整完成凭据，标记为取消后的FAILED，不计作成功率实验。它不是因数值故障、物理失败或预算耗尽而停止。无关GPU进程未操作。

修正时序后的v12已通过入口检查并启动原生128例运行。它采用相同31条参考，其中3条为此前通过完整模型验证的1.6秒长参考，其余为600毫秒参考。原8秒回合、102400环境步和5400秒单作业保护保持。新结果尚未产生。

同时开展相同细模型下的float32时钟配对试验：修正前后各执行TRAIN12、50、58、64、118、123到原回合结束。每次都从记录的真实球分离状态开始，模型状态不传送进Isaac；用于区分时序问题和模型／控制问题。

当前部分结果中，旧索引加float32时钟使TRAIN50、64分别在约0.44、0.42秒发生头部碰地；它们此前在双精度时钟模型中能够完整恢复。这支持时钟表示会实质影响动作执行，但修正版配对结果尚未完成，不能提前声称已恢复这些能力。

## 持续支撑问题仍需解决

上一轮扩展模型中，TRAIN30、61、77在1.6秒结束时仍为三足支撑、明显侧倾，随后转入常规站姿反馈而晚期碰地。这个问题与时钟错误分开处理。

已启动3.2秒全18关节序列搜索，11个控制点全部可调整，优先保持原物理路径约束并获得末尾0.8秒连续稳定；已有1.6秒方案只是初值。搜索围绕实际候选采样，避免平均不同接触过程。末尾仍需再执行到原8秒回合结束，不能以3.2秒模型通过代替完整恢复。

当前判断：完整落脚和加载计划、可持续终态、实际时序一致性都需要同时成立。模型已找到的9个完整恢复候选仍未成为可靠原生教师；本轮不开始蒸馏。
