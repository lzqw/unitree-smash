## 新发现：原生时间导致参考重复一帧

原生时钟来自`episode_length_buf * step_dt`，以float32保存。控制器原先使用：

```python
index = floor(elapsed / 0.01 + 1e-6)
```

例如实际第2步的时间差是`0.019999980926513672`。除以0.01后仍略小于2，原修正量不足，索引成为1。于是参考可能重复上一帧，随后跳过一帧。参考结束条件也受同一舍入影响。

模型测试使用双精度时间，未重现这个执行差异。独立读取已完成原生记录后，31个实际匹配案例共发现**1142次参考索引与整数控制步不一致**。这不是浮点状态比较造成的虚警：记录中的参考索引确实指向前一帧。

新的v12在声明的100Hz控制网格上使用最近整数步，并由整数步决定参考结束和最后100毫秒的参考权重；明显偏离该控制网格的调用会报错。没有改动控制周期、执行器或物理状态。

已执行验证：

- 对录制时钟分别检查60、160、320步参考，共113778项。旧逻辑有27945项索引差异，新逻辑0项；这是多种参考长度的测试组合计数，不等于实际执行中出现27945次错误。
- float32及双精度、多种起始时间的合成检查共24030项通过。
- 新控制器的31条参考、158项真实求解与命令仲裁入口检查通过。

这些是索引和接口证据，不是落地性能证据。不能提前把全部碰地归因于这一错误。

原生参考追踪审计也改用记录中的整数控制步重建期望轨迹，避免审计程序复制同一向下取整问题。逐案例结果见配套JSON。

## 作业处理与当前实验

已经启动、仍沿用旧时序逻辑的v11长参考试验通过本项目GPU守护进程主动停止，保留全部记录。累计耗时约0.015 GPU小时；没有完整完成凭据，标记为取消后的FAILED，不计作成功率实验。它不是因数值故障、物理失败或预算耗尽而停止。无关GPU进程未操作。

修正时序后的v12已通过入口检查并启动原生128例运行。它采用相同31条参考，其中3条为此前通过完整模型验证的1.6秒长参考，其余为600毫秒参考。原8秒回合、102400环境步和5400秒单作业保护保持。新结果尚未产生。

同时开展相同细模型下的float32时钟配对试验：修正前后各执行TRAIN12、50、58、64、118、123到原回合结束。每次都从记录的真实球分离状态开始，模型状态不传送进Isaac；用于区分时序问题和模型／控制问题。

## 再对齐原生接触和阶段逻辑

此前模型验证以“预测冲量大于很小阈值”标记足端接触，并使用简化阶段计时；实际控制器采用地面配对受力的1N／0.5N滞回和`EventRecoveryManagerV1`。两者不能默认等价。

增加的模型对照直接调用同一状态机，使用每个控制间隔最后一个物理子步的预测冲量除以真实子步时间作为足端力估计，保持修正后的float32时钟。每例分别在空中和模型支撑阶段验证记录器不改变动力学，q、v逐位一致。这里的力仍是模型估计，不是PhysX测量。

6例中TRAIN12、50、58、118、123仍完成模型恢复，末尾稳定分别约3.61、3.15、3.98、3.90、3.91秒。TRAIN64在约2.55秒出现右后大腿碰地，不能继续算作这套执行逻辑下的成功候选。

TRAIN64有9个步骤的受力滞回掩码与原预测冲量掩码不同，第一次发生在分离后0.65秒；之后逐步失去支撑。这定位了控制对接触观测方式的敏感性，但尚不能只凭相关时序认定某一个力阈值是唯一原因。下一步必须在完整控制和原生结果中处理轻载、加载和卸载，而不是把阈值改小后直接宣布解决。

## 持续支撑问题仍需解决

上一轮扩展模型中，TRAIN30、61、77在1.6秒结束时仍为三足支撑、明显侧倾，随后转入常规站姿反馈而晚期碰地。这个问题与时钟错误分开处理。

3.2秒全18关节序列搜索已完成300个粗模型候选及细模型复核，耗时927.4秒。11个控制点全部可调整，优先保持原物理路径约束并获得末尾连续稳定；已有1.6秒方案只是初值。搜索围绕实际候选采样，避免平均不同接触过程。

TRAIN61通过3.2秒模型路径，末尾连续稳定0.9秒。修正时钟下继续反馈控制到原8秒回合结束也已完成，525个控制步无模型路径违规，末尾连续稳定约1.72秒。它改善了旧1.6秒候选在分离后约1.97秒碰球拍的模型结果，但仍需使用原生接触状态机及PhysX验证。

TRAIN30通过3.2秒路径但末尾速度和关节运动仍未满足稳定窗口；TRAIN77约2.29秒发生头部碰地。没有把它们标记为教师。TRAIN30仍被纳入完整剩余回合诊断，因为固定3.2秒时刻未稳定不能证明后续不可恢复；只是允许继续评价这个候选，没有降低0.8秒稳定窗口或任何物理条件。

使用原生接触状态机的完整模型测试现已完成，耗时353.2秒。TRAIN30执行完全部523个剩余控制步，末尾连续稳定约2.01秒，没有模型路径违规。TRAIN61则在分离后约4.23秒出现右后小腿碰地：此前最长稳定约0.99秒，但末尾稳定为零。它不能计作完整模型成功，更不能成为可靠教师。这些新参考库独立保存在本地，未替换正在运行的原生v12输入。

TRAIN61在3.2秒参考结束时仍为三足模型支撑，采样稳定已达0.9秒；随后切回通用站姿QP，约3.3秒时只剩两足支撑，横向速度继续增大。碰地当步进入未认证姿态回退，但失稳趋势更早已经出现，不能只把最后一次QP拒绝称为原因。TRAIN30后段也曾三足支撑却最终稳定，可见“三足”本身不等于失败。此处没有增加“四足同时着地”的成功要求，也没有把一次稳定窗口代替原回合末的持续稳定。

这推翻了“TRAIN61已经具有可靠完整恢复”的提前判断：简化接触逻辑下的完整通过不能替代实际控制状态机的对照。新的v13仅在参考结束且观测到支撑后，保存当时实际达到的质心、机身姿态和关节构型作为软目标，继续每步求解原全身QP、使用实时接触与原硬件约束；不是保持最后一帧命令，也不把接触永久锁存。它检验通用站姿切换是否造成不必要的再次运动，没有替换原生v12。

该对照现已完成，耗时354.5秒：TRAIN30仍完成523步，末尾稳定2.01秒；TRAIN61完成全部525步，末尾稳定2.94秒，未出现模型路径违规。两个案例前320步保存的所有共同轨迹字段一致；这些记录不含完整q和最终命令，因此此项对照不能被扩大描述为全状态逐位回放验证。

TRAIN61的新后段持续保留三足支撑，机身侧倾约0.22rad，速度收敛至很小，没有强迫立刻追逐原标准站姿。这支持“参考结束后重新追站姿可能破坏可维持的构型”的假设，仍不是原生安全证明。它也不是固定关节命令：实时QP、阻尼反馈、原执行器限幅和实时接触继续工作。

优化参考终点的足端中心支撑多边形诊断中，TRAIN61质心投影距边界约8.96厘米，定高捕获点近似约6.82厘米，均在内部。此处使用的是优化模型终点而非实际闭环或PhysX状态，且忽略有限足底、角动量与重新落脚，不能用于证明物理可恢复或不可恢复。它仅提醒不能把三足状态直接归因为“质心已在支撑外”。

原六条扩展候选的原生状态机模型对照已完成：TRAIN9、18、42、54、85、90均完成原8秒回合，末尾稳定分别约3.33、3.24、3.05、3.63、3.97、2.88秒。TRAIN42和54分别有209、227步的接触掩码差异，却仍恢复成功，因此不能把掩码不一致次数直接当成失败原因。

新终态反馈的12例模型覆盖检查已完成，耗时624.7秒。TRAIN9、12、18、42、50、54、58、85、90、123共10例完成并最终稳定；TRAIN64约1.02秒球拍触网，TRAIN118虽然完整运行且没有模型路径违规，但稳定窗口始终为零，不能算成功。

TRAIN64在0.6秒参考结束时仍处于反弹，竖直速度约0.62m/s、关节速度约5rad/s；TRAIN118当时侧倾约0.391rad、俯仰约0.319rad，超出原15度稳定范围。无条件保留这样的姿态会固定错误目标：TRAIN118末尾虽几乎停止运动，仍未达到站稳条件。

因此v13不能作为统一控制的已验证改进。原生入口的40条参考、212项命令和仲裁检查虽通过，仍不启动或排队；准备记录明确标为模型退化，当前GPU v12保持原输入。手动入口检查单独保留为manual_entry_check.json，正式运行器若被调用仍会重新执行其声明的入口检查。

新增v14仅调整终态软目标的建立条件：参考结束后，仍用原连续控制处理缓冲；当前姿态、水平/竖直速度、角速度、关节速度进入原有瞬时稳定范围且有观测足支撑、几何无非足部穿地时，才保存实际构型。这不是新增成功判定或“安全域证明”，也不要求冲击期间必须站直。最终仍需原回合末稳定和完整碰撞检查。TRAIN30、61、64、58及单独TRAIN118的完整模型对照已启动，尚无结果。候选检查确认优化终点中61可进入，30、64、118需继续恢复，输入q/v未被检查函数改动。

当前判断：完整落脚和加载计划、可持续终态、实际时序一致性都需要同时成立。上述模型候选仍未成为可靠原生教师；本轮不开始蒸馏。
