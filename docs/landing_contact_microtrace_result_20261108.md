## 为什么第461步拒绝了候选

两条反馈候选的预测路径没有记录到关节位置、硬件速度、力矩或非足部净空超限，但0.8秒预测末端仍未静稳：

| 候选 | 末端最大关节速度 | 末端角速度 | 支撑裕度 |
|---|---:|---:|---:|
| 原机械臂余量反馈 | 3.851 rad/s | 1.315 rad/s | 0.05085 m |
| 机械臂速度预留反馈 | 3.868 rad/s | 1.370 rad/s | 0.04886 m |

原末端要求分别为关节速度≤1 rad/s、角速度≤1 rad/s。这是**候选未满足指定时刻的静稳要求**，不是仅凭日志就能认定动力学无解。

当前461步的记录状态q、v、接触标志、上一实际目标，与此前救回TRAIN3的机械臂余量持续反馈版本在同一时刻完全相同。
这不证明全部PhysX内部接触记忆一致，但说明存在同一已观测状态下成功继续执行的实际对照，不能把一次有限搜索失败解释为物理不可恢复。

另外，旧`records.prediction_error`比较的是原离线名义轨迹，不能用于归因本次新计划。实际被执行的一步，相对它自己的预测，最大速度误差是0.2911 rad/s、最大关节位置误差0.002337 rad、根位置误差约4.17e−5 m。

## 3201个物理帧揭示的接触差异

[新审计程序](../scripts/audit_native_contact_microtrace_v1.py)比较4.60—4.80秒的20个完整控制区间。每个10 ms区间使用其后的160个物理帧，排除上一命令的端点；目标缓冲与实际下发命令及两端关节状态均校验。
原接触标志按力范数1 N接入／0.5 N释放，可从全部记录逐帧精确重建，确认它不是独立几何标志。

| 足 | 原生区间平均法向力 | 平均法向力预测RMSE | 原生标志切换次数 | 模型对齐标志切换次数 |
|---|---:|---:|---:|---:|
| 左前 | 100.04 N | 1.84 N | 0 | 0 |
| 右前 | 20.03 N | 1.19 N | 287 | 3 |
| 左后 | 26.93 N | 0.82 N | 90 | 1 |
| 右后 | 0 N | 0 N | 0 | 0 |

第460步的左后足，以及第475、479步的右前足，控制端点法向力接近零，但该10 ms区间的平均法向力大于1 N。
因此，不能用一个零受力端点推断整个区间没有承载，也不能用高频切换次数直接推断平均支撑预测完全错误。

这组结果支持分别检查**区间承载、接触切换与状态误差**。它不证明模型普遍准确：只有一个案例的0.2秒，且19/20区间执行的是学生回退；最大关节速度RMSE约0.313 rad/s。传感器提供法向力，不包含实测切向摩擦力。

## 下一项控制修改应针对什么

保留严格硬件、接触和恢复要求，下一版应把“短期动作规划”与“经过验证的持续恢复尾段”连接：

```text
当前实测状态与真实上一命令
  → 短期可执行动作候选
  → 在预测末态继续执行持续反馈
  → 检查全段约束、稳定窗口和最终支撑余量
  → 再决定是否下发第一步
```

这不同于把末端速度阈值放宽，或无条件使用失败候选。延长后的尾段也必须预测、检查，并在原生仿真中复测。
第461步至原回合末的160子步延续对照已经完成：原反馈模型合格窗口0.99秒，末态滚转−15.657°；增加姿态反馈后为1.42秒、−13.942°，末态最大关节速度0.0729 rad/s、角速度0.0672 rad/s。两者都完整推进339步，路径检查未失败。
这说明单一0.8秒末点拒绝不等于更长反馈恢复无解；但该检查尚不能替代MPC终端支撑余量、原生接触力和完整事件链验收。结果及文件哈希记录在随附JSON，模型结果不自动成为专家标签。
