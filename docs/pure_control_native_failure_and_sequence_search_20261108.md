## 失败已经能区分为三类问题

### 1. 没有建立持续承载

110个接管案例中，86例接管后出现头部—地面受力超过1N，21例出现其他非足部受力超过1N；这两个集合有重叠，不能相加。

23例在已执行的接管段没有任何非零非足部地面力记录，但没有一例达到0.8秒控制采样稳定窗口。它们随后全部触发原有根节点高度低于0.12米的跌倒终止，终态高度约0.091至0.120米。**这不是只差等待稳定窗口，而是身体仍在塌落。**原终止及成功规则没有修改。

其余一些案例碰头后曾出现较长的低速窗口，也不能算无碰地恢复。准备阶段的头部接触单独保留，不因后段控制而抹除。

### 2. 全关节收束动作需要避网，不能只处理地面

原生机器人触网故障67例。对保存的100Hz真实全身构型做独立网带／网柱几何回算，34例检测到穿入。两者不是同一个检测器：原生接触逐物理步发生，几何回算只有控制采样，且未等价复现PhysX碰撞烹制和接触偏移。因此不能用后者否定前者，也不能拿几何采样时刻充当真实受力时刻。

TRAIN71在2.64秒接管，接管时头部最低净空约0.463米且仍在上升；2.93秒构型中球拍进入网带，3.0173125秒记录到落地段头部受力。这个先后顺序提示需要同时处理挥拍后收束、避网与身体动量，但没有单独证明触网就是碰头的唯一原因。

失败版本的机械臂软参考仍在约0.5秒时间尺度内向默认构型收束，而且执行QP没有网几何约束。这是应替换的参考设计，不能靠增加姿态反馈增益解决。新序列搜索已经直接检查悬空网带和网柱，允许从网下方等实际无碰撞空间运动，不使用无限竖直禁入平面。

### 3. 空中执行预测较准，触地阶段明显失配

本轮新增了“同一个真实状态、同一个实际命令、比较下一实际状态”的一步预测审计，预测步长10毫秒、内部160子步。

触地组另有40例未取得符合条件的连续接触采样对，不能解释为物理上从未碰地；8例模型拒绝，其中7例预测碰网、1例接触／关节求解不收敛。表中误差只统计62个返回预测的样本，没有隐去拒绝。

62例中48例的实际同一步还发生了非足部触地，因此不能把全部差异归咎于足地模型。在“该步无任何非足部地面力、且整回合无机器人触网”的6例中，角速度误差仍为0.136至2.852rad/s，最大关节速度分量误差为2.200至4.761rad/s。这仍可能涉及脚间／其他自碰撞、接触加载和求解方式差异，不是唯一根因证明。

**现在有实测依据将预测修正重点放到接触建立及加载阶段。**空中一步准确不能证明冲击和持续支撑准确；当前局部动力学残差很小，也不等于它与PhysX响应一致。后续需要结合真实足地冲量、脚间接触、关节响应校准这一阶段，同时继续原生候选执行，不等待完美预测器。

### 4. “保护击球前缀”需要跨运行核对

原冻结权重和接管前动作路径保留，但本次110个接管案例中，有42例的出球等记录与历史基线在1e-5比较下不同，出球分量最大差约1.665m/s。

进一步比较严格早于各自接管tick的全部观测和动作，109/110例在1e-6诊断容差内一致，TRAIN114例外。大量差异集中在接触／接管边界对应的物理步，尚未定位其来源；不能将所有球侧变化归因于接管后的控制，更不能声称历史27个案例的击球过程已经逐例完全保留。

下一次需要在接管前独立锁存释放事件、球速度及该步实际状态，并记录网接触的部件与物理时间。接管边界仍须使用因果事件，不能使用未来成功标签。

3. 实现整段18关节位置命令的滚动搜索：优化未来600毫秒，执行模型中前100毫秒，再从更新后的状态重新求解。已完成5次重规划，累计推进模型500毫秒，耗时985.87秒；每次找到的600毫秒候选都通过了该预测器的路径检查。但实际推进到500毫秒时仍只有两足支撑、俯仰约30.5度、水平速度0.502m/s、角速度1.971rad/s，尚未稳定。目标包含速度、角速度、支撑余量及碰撞；不是把单步QP重复调用后称为序列优化。此结果仍是CPU模型实验，尚未接入原生滚动执行，也未满足实时预算。
4. 从本次原生接管记录导出全部110个实际球分离状态，包含q、v、真实足地力、上一最终命令及阶段记忆。已启动同一目标函数下的批量全命令轨迹搜索，使用失败执行命令、原命令保持和状态制动作为初值，并开放所有18维控制点。失败命令只作搜索初值，不是专家标签。

批量搜索的运行状态和滚动搜索的已完成结果见随附紧凑JSON；运行中快照不算冻结成功率。600毫秒预测可行也不是整回合无碰地认证。预测中的接触互补求解失败应单列为数值／模型求解失败，不能直接写成硬件不可能。

## 接下来怎样验收

先让序列控制找到能跨越落脚、缓冲并继续改善支撑的动作，再从原地面前缀进行原生完整执行。重点检查实际足端承重、头部及其他非足部接触、触网、连续稳定与之后是否塌陷。已找到的候选可以直接作为控制实验，不要求模型事先认证余下全部回合；但不能提前当可靠教师。

本轮不恢复学习。优化对象是能持续接住身体的完整控制动作，而不是更多QP通过次数或更大blend。当前没有新增GPU训练作业；CPU序列搜索继续，下一版原生执行仍使用已有GPU0授权及独立故障保护。
