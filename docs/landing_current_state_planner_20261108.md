# 当前状态驱动的完整余程规划器

2026年11月8日。本轮把已经验证的完整恢复参考，接入可重复调用的当前状态规划入口。**模型中的完整余程执行和5次当前状态预测已通过；尚无这套在线规划器的原生成绩，也没有学生学习结果。** 最新完成的另一项避碰名义参考原生对照仍为27/128，严格隔离审计失败。

## 实际控制结构

`CurrentStateRecoveryPlannerV1.solve()`每次接收当前q、v、接触标志、实际上一条命令、原回合控制步，以及已经观察到的连续稳定步数。

它首先从该状态重新预测当前反馈计划一直执行到原第800步的结果。如果完整路径与终端条件通过，再独立重放；一致后才返回可用计划。如果当前计划不通过，则保留已执行修正的时间原点，在当前时刻增加一组连续全身命令修正，并通过结构化采样优化整段余程。

返回的计划可以在两次求解之间根据每一帧实际状态计算命令，**不是重复发送第一次求出的关节目标**。再次求解时，当前状态、接触和命令历史重新进入预测。旧参考生成初态、旧修正的起始时刻不会被悄悄重置。

这属于全身位置目标空间的采样预测控制实现。当前只有模型执行测试，不能提前称为已经部署并验证的原生MPC。

## 优化与验收

- 基础预测仍使用完整加载模型、位置PD和摩擦足端接触求解，不使用理想力矩作为已执行动作。
- 优化变量为当前时刻追加的6组18维命令修正；已执行的修正历史保留。当前时刻新补丁的第一条命令以实际上一条目标为锚点。
- 粗预测仅用于排序。每代24个候选、最多4代，每代最多4个精细候选；精细验证使用160子步/控制步。
- 计划必须完成原回合余下全部步数，满足路径、末态支撑和连续0.8秒稳定条件，并独立重放一致。预算超时不被视为物理不可行。
- 无有效解时明确返回无可用计划，不把失败候选伪装为已接受纠正。调用者仍需明确处理失败，而不是默认计划安全。

当前单次求解计算上限600秒，最多4个CPU工作进程。仿真端可以等待求解；该实现没有实时性声明。真正原生接入时仍须有总作业时间和资源保护。

新增独立CPU规划服务，避免从Isaac入口直接启动多进程时重复导入仿真程序。服务使用私有继承连接、顺序请求号、源文件哈希和当前查询逐项核对，禁用CUDA，并限制工作进程数与求解时间。

实际接口测试在第700步执行100步余程预测及独立重放，39.13秒完成，与已验证参考逐项一致，查询未被替换。随后测试父进程故意退出而不调用正常关闭；服务及其两个子进程均停止执行，父退出资源清理检查通过。该证据只覆盖已测试退出路径，不是所有进程故障的保证，也不是原生控制测试。
